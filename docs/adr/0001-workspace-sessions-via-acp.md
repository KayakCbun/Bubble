# Workspace runs are extra ACP sessions, not Pi subagents

Bubble orchestrates mounted folders by opening a second ACP session (`session/new` with that cwd) on the same `pi-acp` process. A mount may reuse that child session for multiple runs within one main session, but creating a new Bubble main session clears every mount-to-child-session binding so its first workspace run starts with fresh context. Dispatch tools are a Bubble-owned Pi extension in `~/.bubble/workspace/.pi/extensions/`. We rejected Pi subagent packages (they dump child traces into the main transcript and are optional) and ACP `mcpServers` (pi-acp accepts them but does not wire them through).
